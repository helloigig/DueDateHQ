知识工作者
数字能力分级模型

一套基于"思维外化能力"的七级分类框架，用于 SaaS 产品的用户画像与功能设计决策。

7

在构建 SaaS 产品时，"目标用户是谁"这个问题往往被简化为职位或行业。但真正影响产品设计的，是用户能否将自己的思维逻辑转化为系统——能否用工具表达和放大自己的思考。

核心分级逻辑：能否将思维外化为系统。
越高级的用户，越能把自己的逻辑转化为可复用的工具或流程。这个维度，比职位、年龄、行业都更能预测用户行为。

以下七个级别，从顶端的"系统构建者"到底端的"数字消费者"，描绘了知识工作者在数字工具使用上的完整能力谱系。每个级别对应不同的产品设计假设、功能优先级和引导策略。

// 七级能力谱系

L7
顶级
System Builder · 系统构建者
不只用工具，更造工具

能编程，能设计数据结构和 API，把思维直接变成软件。理解抽象、封装和接口的概念，能够设计他人使用的系统。

核心能力：将业务逻辑编码为可运行的程序，在任意领域创造"从无到有"的工具。
编程语言 API 设计 数据结构 工程师 技术创始人
L6
高级
Automation Architect · 流程自动化者
把多个系统串联成管道

不一定写代码，但能用 Zapier、Make、Power Automate 等工具设计跨系统的自动化流程。理解触发器、条件分支和数据流的逻辑，能把重复的手工操作变成自动运行的机器。

核心能力：用"低代码"方式表达流程逻辑，将多个工具的能力组合成超越任何单一工具的系统。
Zapier / Make Webhook 流程设计 运营负责人
L5
中高级
Data Modeler · 数据建模者
用结构来表达逻辑

Excel / Sheets 高手，能写复杂公式、透视表、搭建财务模型；或者熟练使用 SQL 查询数据库；或者能用 Notion / Airtable 搭建有关联关系的结构化数据库。

核心能力：将现实世界的关系和规则，转化为表格结构或查询语言来描述和计算。
Excel / SQL 数据透视表 Airtable 分析师 财务
L4
中级
Power User · 工具深度用户
某一工具的高段位玩家

在某一类专业工具上达到深度掌握——设计师精通 Figma 的组件系统，运营熟悉 GA / Mixpanel 的漏斗分析，产品经理精通 Jira 的自定义工作流。能挖掘出大多数人不知道的高级功能，但能力局限在单一工具内。

核心能力：在垂直领域内最大化单一工具的价值，能够定制和延伸，但缺乏跨工具整合的意识。
Figma Mixpanel Jira 专业领域
L3
中级
Information Synthesizer · 信息整合者
流畅使用，但不定制

能流畅使用多个日常工具——文档、表格、邮件、协作平台。能搜索、筛选、整理信息，产出清晰的报告或沟通内容。但依赖工具的默认用法，遇到需要定制或延伸时会停下来。

核心能力：在既有工具框架内高效完成任务，信息处理能力强，但工具延伸能力弱。
飞书 / 钉钉 Office 套件 信息整理 大多数白领
L2
初级
Task Executor · 任务执行者
按指引操作，遇变化易卡

能完成明确指派的数字化任务——填表、上传文件、基础文字处理。但对工具的理解是操作层面的，而非概念层面的。一旦遇到界面变化或非常规情况，需要逐步指引才能继续。

核心能力：执行既定操作步骤的能力，缺乏对工具底层逻辑的理解，难以举一反三。
表单填写 需要 SOP 传统行业
L1
入门
Digital Consumer · 数字消费者
以消费为主，生产为辅

主要使用手机 App，以消费内容为主。工作场景中的电脑使用和专业软件对他们有一定认知门槛。数字工具在他们的工作场景中扮演辅助角色，而非核心角色。

核心能力：消费数字内容和服务，生产能力有限。SaaS 产品若以此为目标用户，需要极强的手把手引导设计。
手机原生 内容消费 非知识工作者

对 SaaS 产品设计的含义

不同级别的用户，需要根本不同的"能动性假设"。

产品定位

在设计功能之前，先确认你的核心用户在 L 几。给 L3 用户设计 L5 的产品，他们会觉得复杂和焦虑；给 L6 用户设计 L3 的产品，他们会觉得这是个"死胡同"，无法延伸。

API 与开放性

L6+ 用户的标志性需求：API、Webhook、自定义集成。如果产品缺少这些，高级用户会将其定性为"玩具"，而非生产工具。反之，对 L3 用户强推 API 文档则是一种骚扰。

新用户引导

L2 用户需要线性、逐步的操作指引（SOP 化的 Onboarding）。L4+ 用户则厌恶被手把手带着走，他们更需要的是"探索空间"和清晰的文档。

功能命名与抽象层次

L3 用户需要贴近业务语言的功能名称（"发送报告"），L5+ 用户可以接受更抽象的技术名词（"触发器"、"变量"、"数据关联"）。混用会让两类用户都感到困惑。

这个模型不是在评价用户的"优劣"，而是描述不同用户对工具的期望和使用方式。同一个人在不同工具领域可能处于不同级别——一个 L7 的工程师，在使用会计软件时可能只是 L3。

在用户画像中标注目标用户的 Level，可以帮助团队在产品决策时，快速对齐一个关键前提：我们假设用户有多大能力自己掌舵？
